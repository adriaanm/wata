# kid settings (plans 0053/0054/0055): the four-row panel in the dot
# rotation, the help/status rows, the notify tri-state (play/chime/quiet),
# the data row's pick-then-confirm gesture, the hidden development row, and
# the door to the developer panel.

wait syncing 1 900
wait convs 1 900

# dot2 -> the kid settings panel: Notify / Bright / Data / Battery, notify
# selected, the help rows describing it on the bottom two grid rows.
tap dot2
advance 5
checkpoint kid-rows

# the notify row cycles play -> chime -> quiet on OK and both arrows,
# persisted through FbConfig.saveNotifyMode. The default is chime, so one
# step lands on quiet...
tap enter
advance 5
checkpoint kid-notify-quiet

# ...and the next on PLAY — the walkie-talkie mode (plan 0055): arrivals
# speak through the existing auto-play path.
tap right
advance 5
checkpoint kid-notify-play

# one more step returns to the chime default for the rest of the walk.
tap enter
advance 2

# brightness: </> steps the backlight live, same stored preference the
# developer row edits.
tap down
tap left
tap left
advance 5
checkpoint kid-bright

# the data row: what the radios READ is an honest "n/a" on the host; the
# help rows say the gesture (</> pick, OK applies).
tap down
advance 5
checkpoint kid-data

# LEFT/RIGHT cycle the PENDING target only — the yellow ">off" value — and
# nothing touches the radios until OK. From an unknown reading the first
# right lands on `off`.
tap right
expect kidtarget 1
advance 5
checkpoint kid-data-target-off

# two more rights walk wifi -> cell; left steps back to wifi.
tap right
tap right
expect kidtarget 3
advance 5
checkpoint kid-data-target-cell
tap left
expect kidtarget 2

# moving the selection away CLEARS an unconfirmed target — a choice walked
# away from must not linger for a later OK.
tap up
waitmax kidtarget 0 5
tap down

# pick wifi again and CONFIRM with OK: the apply is one Diag call per radio,
# never auto-retried — off-device the guarded "not on device", which the
# help rows state in red. A reporting run KEEPS the target pending (that is
# what OK-again retries), so the probe still reads wifi.
tap right
tap right
expect kidtarget 2
tap enter
advance 5
expect kidtarget 2
checkpoint kid-data-applied

# with the fake-radio seam on (plan 0056), the same OK is answered
# SILENTLY — the commands "ran", which is not the same as the switch being
# done — so the row enters APPLYING: the target with an ascii spinner on
# the black contrast patch, help saying what it is switching to. The
# spinner steps on the applet's own frame counter, so this checkpoint is
# deterministic.
fakeradios on
tap enter
advance 10
expect kidapply 2
checkpoint kid-data-applying

# off-device the diagnostics never agree (still "n/a"), so the wait runs
# out its 75s frame budget — `idle` burns the frames with no real pause.
# In CHUNKS under the screensaver's 60s threshold, with a key the kid
# panel ignores (back) between them: one 2300-frame idle would blank the
# panel, stale the checkpoint, and feed the next tap to the wake-swallow.
idle 900
tap back
idle 900
tap back
idle 600
waitmax kidapply 0 10
advance 3
checkpoint kid-data-timeout
fakeradios off

# the battery row (plan 0054): read-only — the percentage is an honest "n/a"
# on the host — with the help rows saying what it is.
tap down
advance 5
expect kidrow 3
checkpoint kid-battery

# DOWN past the last row lands on the hidden development row — drawn only
# while selected, so the panel stays four rows until now.
tap down
advance 5
expect kidrow 4
checkpoint kid-development

# OK is the door: the ENTIRE developer panel (the old settings applet,
# retitled DEV SETTINGS), outside the dot rotation.
tap enter
advance 5
expect applet 3
checkpoint kid-dev-open

# red returns to the kid settings, still parked on the development row.
tap back
advance 5
waitmax applet 1 10
checkpoint kid-dev-back
