# motion-pump (plan 0077): the rolodex integrator's PHYSICS, probe-only —
# one detent per press, double impulses coasting further, rest exactly on a
# detent. The rendered rolodex has its own scenario (alice-rolodex.txt);
# this one pins the model's numbers. The virtual clock ticks a fixed 33ms
# per frame, so "advance N then expect" is deterministic.
#
# Three users -> three conversations [Family, Bob, Charlie]: room for a
# single detent (centre 0 -> 1) and a two-press double impulse (0 -> 2).

wait syncing 1 900
wait convs 3 900

# settled at the top: centre 0, not moving
waitmax motionlive 0 60
expect motioncentre 0
waitmax motioncentre 0 1

# ONE down press: the impulse is live immediately...
tap down
expect motionlive 1
# ...and a fixed frame budget later it has coasted one detent and stopped
advance 40
expect motioncentre 1
waitmax motioncentre 1 1
waitmax motionlive 0 1

# back to the top the same way
tap up
advance 40
expect motioncentre 0
waitmax motioncentre 0 1
waitmax motionlive 0 1

# TWO quick presses are twice the shove: by the same early frame count a
# single press has only reached centre 1 (see above at advance 40's midpoint),
# the double impulse is already past centre 2 and still coasting
tap down
tap down
advance 8
expect motioncentre 2
expect motionlive 1
# and it comes to rest on the second card, not beyond it
advance 40
waitmax motionlive 0 1
expect motioncentre 2
waitmax motioncentre 2 1

# a HELD key must coast (owner bug 2026-08-27): the keypad's input node
# advertises no EV_REP, so the kernel NEVER autorepeats these keys and a
# held arrow used to deliver exactly one Pressed — one detent, then
# nothing. The frame loop now synthesizes the missing Repeat edges from a
# held arrow (REPEAT_DELAY_S, then one per REPEAT_PERIOD_S), so a hold
# ramps exactly like the injected value=2 trains the hardware floor was
# measured with. Holding DOWN across the list reaches the far end; the
# unfixed loop moved one detent and stopped. The double-press phase left
# the centre on 2, so the hold runs UP: it must land on 0, where a lone
# press lands 1.
key up press
advance 40
key up release
waitmax motionlive 0 90
waitmax motioncentre 0 1
expect motioncentre 0

# and an injected kernel-style repeat still impulses on its own (the
# impulse feed sits ABOVE the press-only gate): press + one repeat is a
# double shove, so from centre 0 it lands at 2 where a lone press lands 1
key down press
key down repeat
key down release
advance 40
waitmax motionlive 0 1
expect motioncentre 2
waitmax motioncentre 2 1
