# settings-walk, phase 2: a second run of the same user, started with no
# credentials, showing that the preferences phase 1 changed came back from
# the config store — brightness 30 rather than the default 40, asserted on
# the KID panel whose row owns it now (plan 0054), and a 2m screen timeout
# rather than the default 1m, asserted on the DEV panel.

wait syncing 1 900

# the type face phase 1 cycled came back from the store: `FbConfig`'s cell
# was primed to inter (2) before the first frame — the restart-restore proof
# for the DEV panel's Type face row.
expect typeface 2

# and the gamma switch phase 1 toggled on came back the same way (primed by
# `loadGammaBlend` in resetCells) — the Gamma blend row's restore proof. The
# frames this phase pins are all plain text/rect draws (no blends), so gamma
# staying on changes none of their bytes.
expect gammablend 2

# the kid panel's Bright row shows the restored 30/40.
tap dot2
tap down
advance 5
checkpoint settings-restored-brightness

# through the hidden development row into the DEV panel; one down from the
# echo row, the screen-off row shows the restored 2m.
tap down
tap down
tap down
tap enter
advance 2
tap down
advance 5
checkpoint settings-restored-timeout

# The screensaver, from the same item: two `<` presses take the timeout from
# the restored 2m down to 30s, then dot1 goes back to the wata applet and the
# session sits idle past it. `idle` runs the frames with no real pause — a
# timer needs simulated time, not network progress — so 30 device-seconds of
# blanking cost the suite nothing.
tap left
tap left
tap dot1
idle 950
expect screenoff 1

# any key wakes the panel, and that keypress is swallowed rather than routed
# into the applet under it.
tap down
expect screenoff 0
