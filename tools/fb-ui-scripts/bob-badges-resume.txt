# badges-across-restart, phase 4: bob restarts with NO credentials (`-` in
# every slot), resumes on the stored token, and the same two badges come
# back — unplayed state is server-side receipt state, so a restart cannot
# lose it. Then one conversation is played out, and only ITS badge clears.
#
# quiet: the resumed session re-primes on its first non-empty snapshot, so a
# split backlog would count its tail as an arrival and play-mode auto-play
# would receipt a message this phase's badges depend on staying unplayed.
# See bob-dm-roundtrip.txt.
notifymode quiet

wait syncing 1 900
wait convs 2 900
wait msgs 1 2000
tap down
# rolodex physics: the impulse has to coast a detent and the pump write the
# new centre into the selection before anything acts on it
wait motioncentre 1 90
waitmax motionlive 0 90
wait msgs 2 2000
tap up
waitmax motioncentre 0 90
waitmax motionlive 0 90
# gate on the summed badge state itself (family 1 + DM 2), then outlast any
# quiet banner a raced arrival raised; both are 0-frame no-ops normally.
wait unplayed 3 2000
waitmax notifybanner 0 200
advance 30
checkpoint badges-restored

# play out the DM only: opening receipts nothing, so both of its rows have to
# be played through before the badge can clear — which is the point of the
# badge. OK on the newest, DOWN, OK on the next. (The first DOWN is on the
# contact screen: rolodex physics, so the OK that opens the DM waits for the
# centre to land on it.)
tap down
wait motioncentre 1 90
waitmax motionlive 0 90
tap enter
tap enter
wait played 1 2000
# the thread scrolls on the motion integrator too (plan 0078): settle the
# detent so the second OK lands on the next row, not the same one again
tap down
wait motioncentre 1 200
waitmax motionlive 0 200
tap enter
wait played 2 2000
tap back
advance 10
checkpoint badges-cleared-one
