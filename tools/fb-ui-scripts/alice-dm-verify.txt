# dm-roundtrip, phase 4: alice's second session pins bob's reply and the
# badge lifecycle — the roster shows one unplayed for the reply, opening the
# conversation receipts it, and the roster afterwards shows no badge.
#
# quiet: a split-backlog sync would otherwise count bob's reply as an
# arrival and play-mode auto-play would receipt it before the badge
# checkpoint (see bob-dm-roundtrip.txt).

wait syncing 1 900
wait convs 2 900
tap down
# rolodex physics: the impulse has to coast a detent and the pump write the
# new centre into the selection before anything acts on it
wait motioncentre 1 90
waitmax motionlive 0 90
wait msgs 2 2000
# same gate as dm-bob-roster: the checkpoint shows the badge for bob's reply,
# so wait for the badge state itself before shooting the frame, then outlast
# any quiet banner a raced arrival raised.
wait unplayed 1 2000
waitmax notifybanner 0 200
advance 30
checkpoint dm-alice-badge

# open and play bob's reply — the top row, the list being newest first. Only
# THAT row becomes played: alice's own message is hers, and no receipt of her
# own was ever posted for it. Both rows are peer-played, though — bob
# receipted alice's message in phase 3 by playing it, and alice's receipt on
# bob's reply counts as a non-sender receipt — so her own row shows the
# double check.
tap enter
advance 30
tap enter
wait played 1 2000
wait peer 2 2000
advance 30
checkpoint dm-alice-reply

tap back
advance 10
