# real one (the settings frames are what these checkpoints pin, but the walk
# starts from a synced client).

tap down

tap left

# then through the hidden development row (three more downs past data and
# battery) into the DEV SETTINGS panel, item 0 (the echo test) selected.

# The diagnostics rows absorbed from system-menu (plan 0003, phase 5). On the
# host the IP and cellular values are an honest "n/a" (no wlan0, no modem);

# The net test: OK runs system-menu's own four probes (gateway ping, 1.1.1.1,
# 8.8.8.8, nslookup). Off the hardware it runs NOTHING — the row answers "n/a"
# and the detail says why, rather than pinging from a dev laptop.
tap down
advance 5
checkpoint settings-nettest

# OK starts the probes on a goroutine and returns — the frame loop does not
# wait on four network round trips. The verdicts land in the applet's state a
# frame or two later, so the run waits for them rather than for a frame count.
tap enter
wait nettest 1 300
advance 5
checkpoint settings-nettest-run

# The radio toggles retired to the kid panel's Data tri-state (plan 0054);
# past the net test the menu scrolls into the power actions. They render
# everywhere but only act on the hardware: OK arms (the detail rows become
# the red confirm prompt), a second OK runs the action — here a logged
# no-op, the device guard.
tap down
advance 5
checkpoint settings-poweroff

tap enter
advance 5
checkpoint settings-poweroff-armed

# OK again on the armed row: off-device this is the guarded no-op — the frame
# after it must show the row back in its unarmed state.
tap enter
advance 5
checkpoint settings-poweroff-run

# arm reboot-to-BL, then move away: any key but OK cancels the confirm.
tap down
tap enter
advance 2
tap down
advance 5
checkpoint settings-reboot-edl
