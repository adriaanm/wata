# settings-walk, phase 1: every DEV settings item in turn, and the two that
# change stored preferences actually changed. The detail block under the menu
# is what these frames are really pinning — it renders on the last two grid
# rows, and every item has its own.

# A room, so the roster the wata applet under this menu was built from is a
# real one (the settings frames are what these checkpoints pin, but the walk
# starts from a synced client).

wait syncing 1 900
wait convs 1 900

# the rolodex's resting frame in the DEFAULT face — the atkinson half of the
# Type face row's live-apply pair (its inter twin is this run's last
# checkpoint, same frame after the cycle).
waitmax motionlive 0 90
advance 5
checkpoint settings-face-roll-atkinson

# dot2 switches to the settings applet — the KID panel (plan 0053). The
# brightness preference now lives here (plan 0054): step it 40 -> 30 on the
# kid row, which phase 2 asserts came back from the store.
tap dot2
advance 2
tap down
tap left
tap left

# then through the hidden development row (three more downs past data and
# battery) into the DEV SETTINGS panel, item 0 (the echo test) selected.
tap down
tap down
tap down
tap enter
advance 5
checkpoint settings-echo

# screen-off timeout: 30s / 1m / 2m / 5m / Never, wrapping — the one stored
# preference this menu still edits (brightness and notify are kid rows now).
tap down
tap right
advance 5
checkpoint settings-timeout

# There is no display-name row: a person's name is their account's, set
# through the admin interface (plan 0021), not picked from presets here.
#
# network and device info: both detail-only.
tap down
advance 5
checkpoint settings-network

tap down
advance 5
checkpoint settings-info

# The diagnostics rows absorbed from system-menu (plan 0003, phase 5). On the
# host the IP and cellular values are an honest "n/a" (no wlan0, no modem);
# on the device they read `ip -4 addr show` and the ppp0 node, which no
# golden can pin.
tap down
advance 5
checkpoint settings-ip

tap down
advance 5
checkpoint settings-cell

# The net test: OK runs system-menu's own four probes (gateway ping, 1.1.1.1,
# 8.8.8.8, nslookup). Off the hardware it runs NOTHING — the row answers "n/a"
# and the detail says why, rather than pinging from a dev laptop.
tap down
advance 5
checkpoint settings-nettest

# OK starts the probes on a goroutine and returns — the frame loop does not
# wait on four network round trips. The verdicts land in the applet's state a
# frame or two later, so the run waits for them rather than for a frame count.
tap enter
wait nettest 1 300
advance 5
checkpoint settings-nettest-run

# The radio toggles retired to the kid panel's Data tri-state (plan 0054);
# past the net test the menu scrolls into the power actions. They render
# everywhere but only act on the hardware: OK arms (the detail rows become
# the red confirm prompt), a second OK runs the action — here a logged
# no-op, the device guard.
tap down
advance 5
checkpoint settings-poweroff

tap enter
advance 5
checkpoint settings-poweroff-armed

# OK again on the armed row: off-device this is the guarded no-op — the frame
# after it must show the row back in its unarmed state.
tap enter
advance 5
checkpoint settings-poweroff-run

# arm reboot-to-BL, then move away: any key but OK cancels the confirm.
tap down
tap enter
advance 2
tap down
advance 5
checkpoint settings-reboot-edl

# the Type face row (plan 0077): the face the rolodex strikes resolve
# against — atkinson by default, cycled with </> like the timeout row
# (immediate apply, no confirm) and persisted through the config store,
# which phase 2 asserts came back. `FbTypeRoles` reads the config cell per
# strike lookup, so the change is live on the next frame — no restart.
tap down
advance 5
checkpoint settings-typeface
expect typeface 1
tap right
advance 5
checkpoint settings-typeface-inter
expect typeface 2

# live-apply, on pixels: back on the wata applet the same resting rolodex
# frame now draws its text in inter — byte-different from the atkinson twin
# pinned at the top of this run.
tap dot1
waitmax motionlive 0 90
advance 5
checkpoint settings-face-roll-inter

# the Gamma blend row (plan 0077): linear-light blending behind a DEV config
# switch, default off — the owner's on-panel A/B. Applet states persist in
# the shell, so dot2 lands the kid panel with its selection still on the
# development door, OK re-opens the DEV panel still on Type face, and one
# down is the gamma row. Pin it off (waitmax — `expect` is >= and cannot
# assert a low value), toggle it on with the timeout row's immediate-apply
# grammar, and LEAVE it on: phase 2's expect is the restart-restore proof.
tap dot2
advance 2
tap enter
advance 2
tap down
advance 5
checkpoint settings-gamma
waitmax gammablend 1 5
tap right
advance 5
checkpoint settings-gamma-on
expect gammablend 2

# live-apply, on pixels: the same resting rolodex frame again, now
# composited in linear light — byte-different from settings-face-roll-inter
# (identical setup but for the blend), which is what proves the switch
# reaches the pixels and not just the store.
tap dot1
waitmax motionlive 0 90
advance 5
checkpoint roll-rest-gamma
