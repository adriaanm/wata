# outrun the SENT flash before opening the conversation
advance 120
tap enter
advance 5
checkpoint conv-top

# twelve downs walk the centre from the newest message (row 0) to the
# oldest — the thread scrolls on the motion integrator (plan 0078), so the
# taps are impulses and the checkpoint waits for the physics to settle on
# the last detent.
tap down
tap down
tap down
tap down
tap down
tap down
tap down
tap down
tap down
tap down
tap down
tap down
# twelve rapid taps are one twelve-detent flick, and a flick COASTS: under
# the integrator's friction it lands one short, on detent 11 — deterministic
# on the fixed 33 ms virtual clock, and exactly the physics the thread now
# scrolls with. The checkpoint pins the coasted-to frame.
wait motioncentre 11 400
waitmax motionlive 0 400
# the scrub chip lingers 18 frames past settle and its text is the wall
# clock's — drain it before the frame is pinned (the chip's own claims
# live in the drawn-thread scenario)
advance 25
waitmax thrchip 0 1
checkpoint conv-scrolled

# back up two rows (settled), then holding red past BACK_HOLD_DELETE redacts
# the selected message (a red TAP would navigate back instead). The row count
# drops, which `wait` cannot see (it tests >=), so `waitmax` asserts it.
tap up
tap up
waitmax motioncentre 9 400
waitmax motionlive 0 400
key back press
advance 30
key back release
waitmax msgs 12 1500
advance 5
checkpoint conv-deleted

# hold OK past OK_HOLD_FAVORITE (0.8s = 25 frames of 33ms) favorites the
# selected message: the row's star only appears once the server's
# net.wata.favorite state has come back through sync, which is what `favs`
# waits on (a short OK tap would play instead).
key enter press
advance 30
key enter release
wait favs 1 1500
advance 5
checkpoint conv-favorited
